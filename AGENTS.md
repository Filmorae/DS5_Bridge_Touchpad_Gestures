# Firmware maintenance notes

- This fork derives from SundayMoments/DS5_Bridge v1.7.1 `main` at `5ee08e0984085c99eac5afe14c05f572b6e9dc59`. Preserve `NOTICE`, `LICENSE`, and the original credits in `UPSTREAM_README.md`. `CUSTOM_PATCHES.md` lists all custom code and rebase checks.
- Custom recognition is in `src/custom_touch_gesture.{h,cpp}`. Inspect actual DualSense contact decoding in `src/dualsense_input_decoder.cpp` before changing contact IDs, coordinates, timing or click interpretation. Inspect the post-processing, pre-forwarding hook in `src/main.cpp`; never delay or queue controller reports to wait for a gesture.
- Shortcut output uses the existing Bridge Keyboard HID interface via `src/companion.{h,cpp}`. Keep key release, queue reset, persona and Bluetooth disconnect behavior. A matching recording click alone is suppressed from the forwarded controller report until its physical release. Do not alter USB descriptors, VID/PID, serial handling, Bluetooth transport, audio, haptics or Companion protocol for these gestures.
- The two literal shortcut sequences are Win+Alt+Print Screen and Alt+F2. Document these as key combinations; host applications and configured bindings vary. Build the Companion-enabled Pico 2 W target (`ENABLE_COMPANION=ON`) and run the host checks with `cmake -S tests/firmware -B build/firmware-tests && cmake --build build/firmware-tests && ctest --test-dir build/firmware-tests --output-on-failure`. Check Pico SRAM use and the time-critical section when the hook changes.
