# Firmware maintenance notes

- This branch derives from SundayMoments/DS5_Bridge tag `v2.0.1` at `ba839b5104ffb775a4f20a3f5426be98b387c1a8`. Preserve `NOTICE`, `LICENSE`, and the original credits in `UPSTREAM_README.md`. `CUSTOM_PATCHES.md` lists the custom code and rebase checks.
- Custom recognition is in `src/custom_touch_gesture.{h,cpp}`. Inspect the DualSense contact decoder before changing contact IDs, coordinates, timing or click interpretation. Run recognition in `process_controller_input_packet` after Companion processing and decoding, with the Bluetooth receive timestamp, before USB publication. Never delay or queue controller reports to wait for a gesture.
- Shortcut output uses the existing Bridge Keyboard HID interface and the staged keyboard tap sequencer. Preserve key release, queue cancellation, persona and Bluetooth disconnect behavior. A matching recording click alone is suppressed from the forwarded controller report until its physical release. Do not alter USB descriptors, VID/PID, serial handling, Bluetooth transport, audio, haptics or Companion protocol for these gestures.
- The two literal shortcut sequences are Win+Alt+Print Screen and Alt+F2. Document these as key combinations; host applications and configured bindings vary. Build the Companion-enabled Pico 2 W target (`ENABLE_COMPANION=ON`) and run the host checks with `cmake -S tests/firmware -B build/firmware-tests && cmake --build build/firmware-tests && ctest --test-dir build/firmware-tests --output-on-failure`. Check Pico SRAM use and the time-critical section when the hook changes.
